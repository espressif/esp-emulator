# What an ESP32-S3 does for each probe in main/main.c, in the same order.
#
#   <index> <op> <addr> <expect> <source>
#
# expect:  ok=<hex>     the access completed and read this value (ok=* : any
#                       value; instruction memory holds whatever the image put
#                       there)
#          exc=<n>      EXCCAUSE of the exception it raised (EXCVADDR == addr)
#          cache-error  IDF's panic handler reported "Cache error" (an
#                       interrupt, not a load/store exception)
# source:  silicon      printed by a real ESP32-S3 running this app
#          gap          printed by silicon, not modelled by the emulator; both
#                       tests report the row and skip it
#
# Silicon run: M5Stack CoreS3, ESP32-S3 (QFN56) rev v0.2, ROM esp32s3-20210327,
# IDF v5.5, 2026-10-05. Its TLB dump after IDF start-up was
# dtlb_ca = F,0,1,2,F,F,F,F (regions 0-7), the attributes tests/xtensa_unmapped.rs
# replays with.
#
# What the rows show:
#   - Unmapped addresses in regions 1-3 do not fault at any width: reads return
#     0 and writes are dropped (0-11, 13-18), including 8/16-bit reads at
#     0x44000000 and up, which is outside the core's instruction-RAM port.
#   - The instruction-RAM port (core-isa.h XCHAL_INSTRAM0, 0x40000000-0x43FFFFFF:
#     ROM, IRAM, flash IROM and the holes between them) takes aligned words
#     only: narrow access is LoadStoreError (3), unaligned word access is
#     LoadStoreAlignment (9) (19-24, 30-34).
#   - Regions 0 and 4-7 (CA 0xF from IDF) raise LoadProhibited (28) /
#     StoreProhibited (29) (25-29).
#   - Row 12, a DROM address behind an invalid MMU entry, is a Cache error
#     interrupt ("MMU entry fault error") on silicon; the emulator reads 0.
#   - S32C1I on a hole loads 0 and raises nothing, whatever SCOMPARE1 holds
#     (35-36); ATOMCTL reads 0x15.
#   - A word access that runs across a region edge is answered per half: a
#     load reads the memory half and 0 for the hole half (46, 49), a store
#     keeps the memory half and drops the hole half (47). The l32i-x/-xh rows
#     seed the memory-side word first and print load ^ (the two aligned words
#     around it), so ok=0 means the halves were answered separately.
#   - Gaps: a word access from the hole below SRAM into SRAM raises a Cache
#     error interrupt when the SRAM word was written just before it (40) and
#     for a store (42); without that write the load reads the SRAM half (49).
#     Writes to 0x3FCFFFFC do not stick (43): with this app's 32 KB data
#     cache, 0x3FCF8000-0x3FCFFFFF is cache memory, not DRAM (IDF
#     heap/port/esp32s3/memory_layout.c gives the heap 0x3FCF0000-0x3FCF7FFF
#     only), which the emulator maps as RAM; so row 41 reads 0 on silicon
#     while the emulator's store lands.
#

# across two boots; row 40 was ok=0 in a run that did not seed the SRAM word).
